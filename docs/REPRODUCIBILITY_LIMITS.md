# Reproducibility limits and known issues

1. **Input compatibility checked:** All four city datasets have been loaded successfully with the unmodified `LLRP_CORE_PARALLEL_HPC.load_city_instance` loader in this archive; the loader reported n, m, Ng, Nv, W, Q and L values matching manuscript Table 5. This check does **not** certify that rerunning stochastic experiments will produce bit-identical results.
2. **Stored results vs recomputation:** Complete case-study source workbooks and merged 30-run benchmark files are archived. Summary extraction is inexpensive; complete 30-run × 20-profile × 5/9-preference reoptimization can take hours/days of CPU time, especially for Isparta.
3. **Solver-specific results:** The exact method (priority-flow MIP, branch-and-price) is excluded. The manuscript's exact comparisons remain visible in the manuscript PDF, but its exact solution code and all solver-specific raw artifacts are not part of this ZIP. Therefore exact optimality certificates cannot be recomputed from this archive.
4. **Historical code:** Some Drive files belong to older projects. The `code/legacy_reference` and `benchmarks/ablation/legacy_report` subfolders are included for traceability and are not intended as the primary publication algorithm.
5. **Potential numerical nonidentity:** Original Python 3.9.23, Numba 0.60.0, Phoenix HPC CentOS 7/Intel Xeon E5-2698 v3, single core per run, 30 processes for parallel sweeps. Different OS/Numba/Python scheduling/random-state handling may change runtimes or stochastic results.
6. **Missing public rights:** The package contains sales, customer codes, and coordinates; the folder was not established as freely distributable research data. Select a data release policy separately from source-code licensing.
7. **Manuscript itself:** Results and exact-reference claims have not been independently recomputed against a solver. No unsupported assertion is made that every paper figure/table is reproducible with one click.
8. **Test scope:** `python tools/check_package.py` validates the presence/schema of the archive and stored run counts, not the theoretical correctness of every neighborhood implementation or the status of the exact solves.

9. **Verified source-to-output divergence (Isparta preference grid):** The production runner originally retrieved from Drive defined `INTERIOR_LAMBDAS = LAMBDAS[1:-1]` for every city and contained no Isparta exception. In contrast, the existing Isparta results and the current manuscript use only five interior weights. We preserved the original runner unchanged under `code/legacy_reference/RUN_TCHEBY_PRODUCTION_PARALLEL_original.py` and made a minimal, clearly commented Isparta-specific edit in the main `code/RUN_TCHEBY_PRODUCTION_PARALLEL.py`. This is a reproducibility alignment change, not evidence that the historical HPC job ran this patched exact script.
